# [T-NT-03] オートソナーのオンセット検出をスペクトラルフラックス+適応閾値に置換する

- 分類: TA
- 優先度: P2
- 評価軸: モーション言語(動きが音楽の性格を語るか)/ モデル一貫性(オンセット=離散イベントの検出器が微分ハックである)
- 依存: T-EMB-01(完了済み)。T-NT-01 と auto-sonar 発火箇所を共有編集(本票を先に実施し発火イベント列を安定させることを推奨)

## 現状(証拠)

対象: `ref/archive_of_the_ninth_tide_shoreless_web/src/main.js`(現行 3062 行)

- AnalyserNode 設定: fftSize 2048、smoothingTimeConstant 0.82、minDecibels -94 / maxDecibels -16(main.js:1974–1978)。周波数データは `getByteFrequencyData`(main.js:2159)。
- transient は**全帯域合成エネルギーの1階微分**: `rawTransient = Math.max(0, energyTarget - state.previousEnergy) * 8.6`(main.js:2182)、非対称ダンプ attack λ26 / release λ7(main.js:2183)。
- オートソナーはこの transient に固定閾値で発火: `state.calibrated && !state.ending && state.playing && state.transient > 0.16 && state.pulseCooldown <= 0` → strength `0.48 + transient * 0.7`、cooldown `1.15 + (1 - low) * 0.7`(main.js:2206–2210)。
- 帰結(research-audio-reactive.md §2.3): 持続音のうねり(クレッシェンド)でも Δenergy が正になり発火する一方、全帯域合算のため高域のみのアタック(ハイハット等)は低域の定常エネルギーに埋もれて取りこぼす。「×8.6」「0.16」は耳当て定数で音楽的根拠がない。
- 展示コンセプト上、オートソナーは「ビート同期した九章が物質法則を書き換える」計器の自動読み取りであり、発火が音楽的イベントと非同期に見えることは演出の信頼性を直接損なう(カルテ「コンセプト」節)。

## 問題

オートソナーの発火が「新しい音の立ち上がり」ではなく「音量が増えた瞬間」に反応するため、静かな章では無音のうねりで鳴り、激しい章では実際のアタックとズレる。展示の主要な自動演出が音楽と半端に同期していることは、オーディオリアクティブ展示としての説得力の核を弱める。

## 改善方向

research-audio-reactive.md §2.3 の実装要点(ライブラリ不要、JS 約30行)をそのまま適用する:

- **スペクトラルフラックス**: 前フレームの `freqData` を保持し `flux = Σ max(0, freqData[i] - last[i])` — 「エネルギーが増えたビンだけ」を合算し、新しい音の立ち上がりに選択的に反応させる。
- ODF をローパス(既存 `damp()` 流用)してノイズ除去。
- **適応閾値**: 直近 1〜1.5 s のリングバッファで移動平均 μ と標準偏差 σ を保持し、`flux > μ + k·σ`(k≈1.5–2.0)かつ局所極大でオンセット。固定 0.16 閾値を置換する。
- 不応期(refractory)は現行 cooldown 機構(:2209)と統合。
- 低域ラムブル対策として 190 Hz 以上に限定した**帯域限定フラックス**を併走させ、章ごとにどちらをトリガに使うか選べる設計にする(演出の幅)。
- **置換は離散イベント(オートソナー発火)のみ**。コアの呼吸・veil 等が参照する連続エンベロープ `transient` は現行のまま維持し、視覚回帰を避ける(§2.3 の低リスク方針)。
- 合成スペクトラム経路(静默入場・一時停止時のフォールバック)でもフラックス計算が例外なく動くこと(合成データは定常なので発火頻度が下がるのは正しい挙動)。
- Meyda / Essentia.js は導入しない(Essentia.js は AGPLv3 でライセンス不適合リスク、自前30行で足りる — §2.3)。

## 受け入れ基準

- 数値: archive.mp3 の代表2区間(持続音クレッシェンドを含む静区間、ハイハット系アタックを含む密区間)で発火タイムスタンプをログし、オフライン参照(librosa `onset_detect` 等による同区間のオンセット列、±80 ms 許容)に対する precision / recall が現行 transient 方式より両方改善すること。比較ログを docs/direction/ の QA ログ(T-NT-05 で新設)に残す。
- 挙動: クレッシェンド区間で誤発火ゼロ(現行は発火する)、密区間で高域アタックの取りこぼしが減ること。
- 回帰なし: `transient` 連続エンベロープ由来の視覚(コア呼吸、カメラロール、veil chroma)が preview 決定論キャプチャで変化しないこと。静默入場(合成スペクトラム)経路でコンソールエラーゼロ。
- 発火頻度がオートソナー cooldown 設計(1.15–1.85 s)と整合し、パルス系を飽和させないこと。
